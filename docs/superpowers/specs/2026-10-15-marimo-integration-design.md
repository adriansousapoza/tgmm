# marimo integration: design

Date: 2026-10-15. Implements "tgmm docs: marimo integration plan" (Oct 15, 2026). The plan's decisions are not
reopened here; this document records what was built, where it lives, and the deviations.

## Constraint that shapes everything

PyTorch has no WebAssembly wheel, so nothing that imports `tgmm` can run in the reader's browser. marimo is
therefore used in three modes:

| Mode | What runs where | Used for | Files |
| --- | --- | --- | --- |
| A. Author in marimo, publish static | notebooks execute in CI with CPU torch, are exported to `.ipynb` with outputs, rendered by `mkdocs-jupyter` | all 18 tutorials | `notebooks/*.py`, `.github/workflows/docs.yml` |
| B. `mkdocs-marimo` islands | pure NumPy/SciPy/matplotlib in the browser via Pyodide | 4 explainer pages | `docs/explainers/*.md` |
| C. Hosted sessions | molab runs the real notebook on a server | "Open in molab" badge per tutorial | `scripts/postprocess_notebooks.py` |

The Hugging Face Space (plan D.2) is deliberately not built; the plan defers it until D.1 has shipped.

## Source of truth and generated files

- `notebooks/NN_name.py` (marimo) is the only committed form of a tutorial. `docs/notebooks/*.ipynb` is generated by
  `marimo export ipynb --include-outputs --sort top-down` and is git-ignored. `docs/notebooks` used to be a symlink
  to `../notebooks`; it is now a real directory holding only generated files.
- The published URLs are unchanged: `mkdocs-jupyter` derives `/notebooks/NN_name/` from the generated file name, and
  the `.ipynb` links used throughout the docs and between notebooks still resolve.
- Tutorials are numbered 01-18. The plan was written for 12 notebooks; 13-17 existed by the time of the migration, and
  the Student-t / von Mises-Fisher notebook was split into 16 (`16_student_t`) and 17 (`17_von_mises_fisher`), so
  semi-supervised fitting became 18.

## Notebook conventions

Defined in `notebooks/README.md` and enforced by `marimo check` plus `tests/test_notebooks.py`:

- PEP 723 header with `torch; sys_platform != 'emscripten'`; `app = marimo.App(width="medium")`.
- A config cell turns `TGMM_DOCS_FAST=1` into `FAST`, `MAX_ITER` (100 / 1000) and `N_INIT` (1 / 5); slow calls use them.
- Unique global names (distinct names, or underscore-private scratch names); figures are the last expression of
  their cell (`plt.gcf()`), one per cell; no `os.chdir`.
- The seed variable is `SEED` and keeps each notebook's historical value (not a global 42), so results and the prose
  that describes them do not change.

## CI (`.github/workflows/docs.yml`)

Two jobs on `ubuntu-latest`, Python 3.11, CPU torch:

1. `notebooks-test` (every PR and push): `marimo check notebooks/`, then `pytest -m notebooks` (each notebook as a
   script, `TGMM_DOCS_FAST=1`, `MPLBACKEND=Agg`, 180 s timeout).
2. `build` (every PR and push; deploys on pushes to `main` only): export every notebook, post-process, `mkdocs build
   --strict`, `mkdocs gh-deploy --force`. Notebook outputs are never cached.

`tests/test_notebooks.py` is excluded from the default `pytest` run through `addopts = -m "not notebooks"` in
`pytest.ini` (the repository configures pytest in `pytest.ini`, not `pyproject.toml`).

## Deviations from the plan

- **Post-processing script.** The plan's `scripts/add_molab_badges.py` is `scripts/postprocess_notebooks.py`: besides the
  badge it also removes the two plumbing cells (`import marimo as mo` and the `FAST` config cell, marked with the
  comment `# docs: hide-cell`) from the exported pages, so a reader sees the tutorial rather than its scaffolding.
  It is idempotent and offline.
- **Dependencies header.** The header lists `tgmm` (PyPI), as the plan specifies. `marimo edit --sandbox` and molab
  therefore install the *released* package; features that are only on `main` (for example `plot_vmf`) are available there
  after the next release. In a clone, use `pip install -e .` and run without `--sandbox`.
- **Dependency pins.** `docs/requirements.txt` pins `marimo` and `mkdocs-marimo` exactly, and adds the scientific
  packages the notebooks import.

## Explainers (`docs/explainers/`)

Four `mkdocs-marimo` pages (`gpcm-shapes`, `em-stepper`, `annealing`, `metrics-intuition`). Each is one island notebook
of at most ~150 lines of code, written as ```` ```python {marimo} ```` fences; imports are limited to numpy, scipy,
matplotlib and marimo; seeds and data are fixed so the build-time render equals the first view; click state uses
`mo.state`. Screenshots of each page's initial render are in `docs/explainers/screenshots/`.

**Pitfall found in a real browser.** The plugin emits each island as an inline `<marimo-internal-island>` tag, which
Python-Markdown wraps in a `<p>`. A layout output (`mo.hstack`/`mo.vstack`, a `<div>`) makes the browser close that `<p>`
early and tear the island apart, so the cell's code is never registered and dependent cells fail with `NameError` in
Pyodide (console: "Embedded marimo app main missing cell output or code"). Stubbed headless tests do not see it. Every
fence is therefore wrapped in `<div markdown="0">`, which keeps it out of a paragraph. Verified with Chromium
(Playwright) by changing the controls on all four pages.

## Verification

- `marimo check notebooks/` clean; every notebook runs as a script with `TGMM_DOCS_FAST=1` in under 3 minutes.
- Each tutorial was compared against its pre-migration version section by section (headings, figures, conclusions).
- `mkdocs build --strict` passes with the plugin enabled.
- Explainers were opened in Chromium (Playwright) and their controls exercised. Not verifiable locally: the GitHub Actions
  run itself, molab, and Pyodide in Firefox. The workflow's steps are the
  `make docs-build` steps, which were run locally.
